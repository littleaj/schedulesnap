# Contributing

Thank you for your interest in contributing! Contributions of bug fixes, improvements, documentation, tests, and other enhancements are welcome.

## Getting Started

Before making a substantial change, please open an issue to discuss your proposed approach. This helps avoid duplicated effort and ensures the change fits the project's goals.

For small fixes, such as correcting a typo or fixing a straightforward bug, feel free to open a pull request directly.

Please check existing issues and pull requests before starting work.

## Development Setup

To work on the project locally:

1. Fork the repository on GitHub.
2. Clone your fork.
3. Install the project dependencies.
4. Create a branch for your changes.
5. Run the application locally and verify your changes.

### Commands

```bash
# Install dependencies
npm install

# Start the development server
npm run dev-storage && npm run dev

# Run tests
npm test

# Run the production build
npm run build
```

Local development and testing are permitted under the project's source-available license.

## Making Changes

Please keep changes focused and consistent with the existing codebase.

- Follow the project's existing code style and conventions.
- Add or update tests when appropriate.
- Update documentation when behavior or configuration changes.
- Avoid unrelated refactoring in otherwise focused pull requests.
- Do not commit secrets, credentials, personal data, or local configuration containing sensitive information.
- Ensure that tests and the production build pass before submitting a pull request.

If you're unsure how a change should be implemented, ask in the relevant issue before investing significant effort.

## Pull Requests

When opening a pull request:

- Explain what the change does and why it is needed.
- Link any related issues.
- Describe how you tested the change.
- Include screenshots or other evidence for user-facing changes when helpful.
- Identify any known limitations or follow-up work.

Keep pull requests as focused as reasonably possible. Maintainers may request changes, ask questions, or close a pull request that falls outside the project's scope.

Submitting a pull request does not guarantee that the contribution will be accepted or merged.

## Reporting Bugs and Requesting Features

Please use GitHub Issues to report bugs or suggest improvements.

For bug reports, include:

- Steps to reproduce the problem.
- Expected and actual behavior.
- Relevant error messages or logs.
- Your environment and relevant version information.

For feature requests, describe the problem you want to solve and why the proposed change would help.

Do not include passwords, API keys, access tokens, or other sensitive information in issues.

## Security Issues

Please do not disclose exploitable security vulnerabilities in public issues. Contact the maintainer privately through the security reporting method documented in the repository.
